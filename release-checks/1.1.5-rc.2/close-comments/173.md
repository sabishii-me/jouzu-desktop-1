Fixed in **1.1.5-rc.2** (QA channel) by #220 (commit f3dc8a0; release commit 120b2f0).

**What changed:** An environment change gives open sessions a new runtime, so the new value reaches them.

**Verified on 1.1.5-rc.2** with the independent QA playbook (deterministic local provider, throwaway data dirs), compared with 1.1.4 on the same setup.
Where: Windows 11 x64 release package (environment overrides are stored on Windows only).
- Change a variable in Settings > Environment while a session is open: that session uses the new value without restarting the app. 1.1.4 keeps the old one.

**Regression scenario:** QA playbook case "#173 An environment change reaches the open session".
