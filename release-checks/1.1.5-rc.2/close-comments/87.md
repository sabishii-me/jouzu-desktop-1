Fixed in **1.1.5-rc.2** (QA channel) by #220 (commit b53f100; release commit 120b2f0).

**What changed:** Retry at the start page asks the host again after the runtime's files were reported missing, instead of staying on Connecting.

**Verified on 1.1.5-rc.2** with the independent QA playbook (deterministic local provider, throwaway data dirs), compared with 1.1.4 on the same setup.
Where: Windows 11 x64 release packages and a Linux build of the release commit, English and Japanese.
- Start with the runtime's files missing: the start page says the files are missing (no endless Connecting).
- Retry while they are still missing keeps saying so.
- Files put back, Retry: a session opens in about 40 ms and answers. 3 of 3 on Windows, en and ja.
- 1.1.4: Retry disappears, the window stays on Connecting and no session opens.

**Regression scenario:** QA playbook case "#87 Retry after the runtime's files come back".
