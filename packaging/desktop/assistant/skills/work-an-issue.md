# Work an issue

1. Read what the user said about the issue. If you only have its number, start a short read-only task to summarise it (title, labels, what is asked, what evidence exists, linked issues and pull requests) before planning.
2. Check for duplicates and related open work in that summary; group issues with the same cause into one task.
3. Write the brief (write-a-brief). For a bug, ask for root cause first and for the evidence that shows it. Tell the task the repository's branch rules: work on a new branch, open the pull request into the development branch, never push to the default branch, never merge.
4. Follow up (follow-up) and accept with evidence (accept-with-evidence).
5. Report to the user with the pull request link and the evidence. Merging and releasing are the user's.
6. A new problem found on the way is not fixed silently: ask the task to describe it so the user can file it, or note it in your report.
